# HOME OS — Engineering & Security Risk Register

| ID | Category | Risk Description | Likelihood | Severity | Mitigation Strategy | Status |
|---|---|---|---|---|---|---|
| **R-01** | Security | Accidental exposure of local control server to untrusted networks or public internet | Medium | Critical | Default `HOMEOS_BIND_HOST=127.0.0.1`; mandatory Argon2id + session auth; rate limiting; CORS allowlist; TLS certificate auto-generation. | Mitigated by design |
| **R-02** | Security | Plaintext storage of Home Assistant tokens or device secrets in SQLite | Medium | Critical | Envelope encryption (`AES-256-GCM`) keyed via `0600` master vault / OS keyring; device tokens stored exclusively as SHA-256 hashes. | Mitigated by design |
| **R-03** | Security | Replay of captured LAN device telemetry or command acknowledgements | Medium | High | Every signed agent frame/request includes `timestamp` (`±60s` window) + unique `nonce` validated against bounded replay cache + HMAC-SHA256 signature. | Mitigated by design |
| **R-04** | Security | Directory traversal (`../../etc/shadow`) via file browsing or transfer endpoints | Medium | Critical | `os.path.realpath` canonicalization enforced on both server and native agents against explicit authorized root directories; regression-tested in security suite. | Mitigated by design |
| **R-05** | Security | SSRF or XXE injection via malicious UPnP/SSDP `LOCATION` XML broadcasts on LAN | Medium | High | `defusedxml` blocks XXE/entity expansion; `LOCATION` host strictly validated as private LAN IP before fetch; strict 2s timeout & 64 KB response cap. | Mitigated by design |
| **R-06** | Platform | iOS sandbox prohibits SMS, call history, global notifications, and remote touch | Certain | Medium | Explicitly documented in UI & iOS companion; supported Apple alternatives (`Shortcuts`, `AppIntents`, `HomeKit`, security-scoped files) implemented cleanly. | Accepted & documented |
| **R-07** | Platform | Google Play restricts `READ_SMS`, `READ_CALL_LOG`, and `AccessibilityService` | Certain | Medium | Companion separates `NotificationListenerService` (Play-eligible notification & WhatsApp inline reply) from optional direct-APK SMS/Call/Accessibility permissions with clear onboarding & revocation. | Mitigated & documented |
| **R-08** | Environment | Cloud build sandbox lacks physical mobile/TV hardware and Apple/Android/.NET native toolchains | Certain | Medium | Full native source trees + CI build pipelines created; protocol-level wire tests verify Android TV v2, Home Assistant WS/REST, Matter JSON-RPC, and Agent WS protocols; Linux agent verified live on host; hardware verification status transparently reported. | Tracked in `PROJECT_STATUS.md` |
| **R-09** | Safety | Automation accidentally executes destructive or physical security action (e.g., smart lock unlock) | Low | High | Capabilities flagged `requires_confirmation=True` halt execution in `pending_confirmation` / `awaiting_confirmation` until explicit operator approval. | Mitigated by design |
